=============================
DW99 内核移植与启动排障记录
=============================

项目与对照基线
==============

DW99 使用展锐 SL8541E（SharkLE）平台。本仓库的 7.3 分支以
``upgrade-linux-7.3`` 为工作分支。厂商行为以 Watch-GKI 4.4.147
的 DW99 配置、设备树和驱动为对照，审查时的提交为 ``4d3de52cc``。
用户态兼容以现有 HyperOS 调试版的 ``vendor.img`` 为对照，其中的
厂商模块原先面向 Linux 4.14.133。

DSH 阶段
========

1. 将 DW99 主线测试树更新至 Linux 7.3.4，保留原有板级驱动和设备树，
   处理内核升级产生的接口冲突并恢复 ARM64 编译。相关基线见
   ``d4de4ef72``、``40fe4644c`` 和 ``5195dbf4f``。
2. 根据多轮早期启动日志，修复 PTM 通道名在读取通道数量之前分配、
   SharkLE 深睡眠 regmap 错误处理等问题（``93c55958c``、
   ``ffe6e2c98``）。随后将启动控制台收敛到 USB，保留 U-Boot
   早期端点的 ``musbec``，配置 ``keep_bootcon console=ttynull``
   （``a3d5ca639``）。
3. 修复 WLAN 提前调用 WCN 所致的空指针，通过探测延迟等待 WCN 和
   硬件锁就绪（``7b04b003e``）。调整 ADI 父设备运行时电源管理
   （``d9d66fc37``）。随后修复 SC2721 电源供应和 FGU 注册失败后的
   错误处理（``07ddc1caf``）。后续归档日志已显示 FGU 成功完成探测。
4. 对照本地原厂启动链找到 SC2721 PMIC 看门狗复位方式，将其接入
   DW99 的正常重启和 panic 复位路径，并提前注册到 FGU 探测之前
   （``1a94876fe``、``32863d444``）。DSH 已构建并打包 PMIC 复位
   镜像，远端构建通过。实机复位行为仍需验证。
5. 多次启动采集仍出现随机截断。可核对的一次归档使用
   ``32863d444``，约在启动后 0.339571 秒截在 DSI 初始化消息中途。
   DSH 已开始排查 USB PHY 接管及 ramoops、PWM、mailbox 警告。
   后续调用遇到请求配额和授权错误，停在源码分析阶段。

Codex 接续
==========

重新定位整理后的 Windows 端工具和 WSL 工作树，核对实际构建配置，
继续使用同一 7.3.4 基线。本地诊断工作修复 PWM 驱动重名和
``pwm_chip`` 注册问题，把 ramoops 改成 7.3 能识别且按 4 KiB 对齐的
预留内存节点，并为 DW99 的两条 mailbox SPI 显式声明当前 GIC 初始化
采用的电平触发。ramoops 保留原厂预留范围，并为控制台配置 128 KiB。
同布局内核可以在保持该段 RAM 的重启后读取记录。

正常诊断镜像保留 MUSB 与 USB PHY，记录 PHY 供电、探测断电和控制器
复位。对照镜像仅在生成的 DTB 中禁用 MUSB 和 PHY 两个节点，两份
镜像内的 ARM64 内核及 ramdisk 完全相同。编译、DTB 比对和 SPRD
封装逐段校验均已完成。对照镜像用于区分驱动接管与其他日志中断原因，
其正常 USB gadget 功能随节点一起关闭。USB 早期控制台直接写引导器
遗留的 EP5，Watch-GKI 的常规 PHY 探测会主动断电及隔离，构成一个
明确的待测断点。现有记录仍不足以确认每一次日志截断的原因。

Windows 采集器改为有限超时读取，记录端口静默、消失和重连，同时独立
保存原始字节和事件流。现有 FDL 批处理在原命令成功退出后启动采集器，
使用自动识别的 SPRD 端口。成功、FDL 失败及采集失败均经过命令模拟，
设备端采集仍待验证。

Watch-GKI 驱动审查
==================

两份 DW99 DTB 各保留 315 个自身及祖先均启用的 compatible 节点。
逐项核对了匹配表、生成配置、链接符号和 ROM 用户态接口，确认以下
影响启动或兼容的差异。

* USB UDC 移植丢失厂商 charger 初始化、状态通知和退出调用，
  MUSB glue 仍直接使用 charger 指针。
* SC2721 的 ``INT_EN`` 在新版 regmap IRQ 接口下被当作普通
  mask 寄存器。ADC 的 IIO 回调和底层函数重复获取同一把 mutex，
  板温读取可以在启动中触发。ADC 及 PMIC eFuse 还有硬件锁语义差异。
* SIPC 从旧四参数 ``vm_map_ram`` 切换到新版三参数接口时，
  丢失了本应给 SWCNBLK 共享控制环使用的非缓存页保护属性。
* ADF 和 JPEG 的 32 位 ioctl 分派被替换为返回 ``-ENOTTY`` 的
  占位实现。部分相机、VSP 和 ION 的兼容入口也缺少有效缓冲区。
  ROM 里确实存在使用这些接口的 32 位厂商库。
* 现有构建的厂商 GPU、蓝牙和 FM 模块尚未交付。ROM 的原模块和
  7.3 具有不同的内核符号版本，WLAN 则已有内建实现。

兼容路径与验证状态
==================

* Mali。ROM 的内核模块和 Watch-GKI 源码均为
  ``r28p0-01rel0``、UK ABI ``11.13``。保留 ``/dev/mali*`` 及
  现有 ioctl 是复用 HyperOS EGL/GLES 库的目标。Watch-GKI 已有
  SharkLE 电源管理和调频实现。移植时需核对 dma-buf、内存映射、
  页固定、shrinkers 和 32 位 ioctl，再进行实机渲染验证。
* 蓝牙和 FM。使用 Watch-GKI 的 SIPC 源码，保留 ``sprdbt_tty.ko``、
  ``sprd_fm.ko``、``/dev/ttyBT0``、``/dev/fm`` 和 FM 的 32 位
  ioctl。现有 Android init 已按这些模块名加载。优先修复共享控制
  环的映射属性及固件读取逻辑，然后基于同一 7.3 构建的符号版本
  生成模块。实际 WCN 启动、蓝牙和 FM 功能仍需板上验证。
* 构建验证的范围包括 ARM64 内核链接、DTB、诊断镜像封装及 Windows
  采集器离线流程。兼容驱动移植已开始，后续以目标内核的模块构建和
  ABI 校验结果更新本记录。
